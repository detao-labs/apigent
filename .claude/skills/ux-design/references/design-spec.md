# 页面设计规范（Page Design Spec）

UX 稿的默认布局模式与交互要求。无特殊要求时按此执行；页面设计相关反馈应回写到本文件。

## 1. 默认布局模式

- **全局顶栏**：左品牌；右依次为通知、系统设置（主题/语言/关于）、用户菜单（个人信息/设置/退出登录）。用户信息不放侧栏。
- **主侧栏**：仪表盘置顶、无分组标签；功能按用途分组（如「工作台」= 组织+仓库）；设置作为独立一级菜单固定在左下角；API 密钥等账号级功能放设置页，不进侧栏。
- **详情页独立 rail**：详情页操作密度高时（如仓库详情），用左侧页面级菜单（概览/接口/模型/上下文/版本/设置）替代横向 Tab，内容区更宽；左下角只放「← 返回列表」。
- **设置页**：独立页面（非弹窗），自带分组菜单（用户信息/偏好设置）；左下角「← 返回仪表盘」。弹窗只做瞬时操作（确认、一次性密钥）；会增长的内容一律用页面。
- **品牌**：副标题用一句话定位（如「为Agent而生」），不用泛词「平台」。

## 2. 交互要求

- 全部可点击：toast、确认框、popover、Tab、弹窗/抽屉、主题切换（真实生效）、表单校验、复制、筛选、空状态。
- V1 未实现的功能点击后 toast「V1 待实现」，不得无响应。
- 交互统一写在共享 `mockup.js`（toast/confirm/modal/theme/tab），样式走 CSS 变量，保证全站一致。
